# Daemon configuration reference (`daemon.toml`)

Every running daemon is configured by a single TOML file (typically
`/etc/otzi/daemon.toml` on a .deb install; anywhere for tests). This is a
field-by-field reference; for operator workflows (bootstrap → DKG → enable),
see [`install.md`](./install.md).

TOML uses `snake_case` keys. The parser is strict — missing required tables
and unknown enum values throw `ConfigError` with the dotted field path.

## Shape at a glance

```toml
[share]
path         = "/var/lib/otzi/share.json"
password_env = "OTZI_SHARE_PASSWORD"

[node]
id            = "node-a"
party_id      = 0
# Paths below are required for real-network transports (not in-memory tests).
identity_key_file = "/var/lib/otzi/identity.json"
pubkey_book_file  = "/var/lib/otzi/pubkeys.json"

[network]
name      = "testnet"                       # "mainnet" | "testnet" | "regtest"
opnet_rpc = "https://testnet.opnet.org"

[transport]
kind   = "peer-mesh"                        # "peer-mesh" | "relay"
listen = "0.0.0.0:8800"                     # required for peer-mesh
# url  = "ws://relay.example:9000"          # required iff kind = "relay"

[[peers]]
id             = "node-b"
party_id       = 1
wallet_address = "0xabc..."                 # 0x + hex(SHA256(mldsaPubKey))
endpoint       = "ws://node-b.example:8800" # peer-mesh only; omit for relay

[gate]
strategy = "auto"                           # see § Gate strategies

[deadlines]
signing_ms = 300000                         # default
dkg_ms     = 900000                         # default

[[triggers]]
kind = "http"
bind = "127.0.0.1:7080"
# auth_token_env = "OTZI_API_TOKEN"         # optional Bearer auth
```

## `[share]` (required)

| Key | Type | Notes |
|---|---|---|
| `path` | string | Absolute path to the Ötzi-compatible encrypted V3 share JSON file. Missing file at startup → daemon runs in DKG-only mode (signing rejected; `otzi generate` populates it). |
| `password_env` | string | Name of the env var holding the share-file password. The password itself is never stored in the config. |

## `[node]` (required)

| Key | Type | Notes |
|---|---|---|
| `id` | string | Logical identifier (e.g. `node-a`). Must be unique across the ring; must match the peers' view of this node's `id`. |
| `party_id` | integer ≥ 0 | 0..n-1 partyId. Must match the decrypted share's `partyId` at load time — mismatch → startup fail. |
| `identity_key_file` | string, optional | Path to this node's PKCS#8 ECDH identity key (generated by `otzi setup`). Required for real transports; optional for in-process tests. |
| `pubkey_book_file` | string, optional | Path to the JSON pubkey book produced by `otzi setup`. Required for real transports. |

## `[network]` (required)

| Key | Type | Notes |
|---|---|---|
| `name` | `"mainnet"` \| `"testnet"` \| `"regtest"` | Network the federation operates on. On `mainnet`/`testnet`, combined DKG includes the key-link FROST sign phase (produces `frostLegacySig`). On `regtest`, the key-link phase is skipped — OPNet contract calls against the resulting vault will fail at capture (SDK expects a valid `frostLegacySig`). |
| `opnet_rpc` | string | OPNet RPC URL. Operator-side broadcast paths default to this; the daemon itself doesn't consume it at runtime. |

## `[transport]` (required)

| Key | Type | Notes |
|---|---|---|
| `kind` | `"peer-mesh"` \| `"relay"` | See `CLAUDE.md` § Transport. `peer-mesh` = direct WebSocket between daemons. `relay` = tiny Node relay (`~150 LOC`) routes opaque frames. |
| `listen` | string | Required when `kind="peer-mesh"`. `host:port` for the peer WS server (e.g. `0.0.0.0:8800`). |
| `url` | string | Required when `kind="relay"`. `ws://` URL of the relay (e.g. `ws://relay.example:9000`). |

## `[[peers]]` (required — at least one)

One entry per *other* node in the ring (this node is implied by `[node]`).

| Key | Type | Notes |
|---|---|---|
| `id` | string | Matches the peer's own `[node].id`. |
| `party_id` | integer ≥ 0 | Matches the peer's `[node].party_id`. Must be unique across the ring. |
| `wallet_address` | string, optional (required for real transports) | `0x` + hex(SHA256(mldsaPubKey)). Produced by bootstrap and visible in `/var/lib/otzi/pubkeys.json`. |
| `endpoint` | string, optional | WebSocket endpoint (`ws://host:port`). Required for `peer-mesh`; absent means relay-only routing to this peer. |

The parser rejects duplicate `id`s or duplicate `party_id`s across node + peers.

## `[gate]` (required)

Controls which ceremonies this daemon will join. See [`gates.md`](./gates.md)
for the contract. The `[gate]` table contains `strategy` plus strategy-specific
params directly (flat, not under a sub-table).

| Strategy | Meaning |
|---|---|
| `auto` | Always approve. Default for pure-headless deployments. |
| `policy` | Rule engine over structural `CeremonySpec` fields. Strict-by-default (rejects anything not matched by a rule). |
| `exec` | Spawn operator-supplied command; approval = first line of stdout. |
| `webhook` | POST spec JSON to a URL; approval = `{ "decision" }` response. |
| `cli` / `queue` | Reserved — throws at gate construction. Write an `exec`/`webhook` gate against `examples/gate-file-approver.sh` instead. |

### `strategy = "auto"`

No params.

```toml
[gate]
strategy = "auto"
```

### `strategy = "policy"`

All sub-fields are optional; each narrows what the gate will approve.

| Key | Type | Applies to | Notes |
|---|---|---|---|
| `max_amount` | integer \| decimal string | Any signing | Hard cap on spec `amount`. |
| `destination_allowlist` | string[] | Any signing | Exact-match against spec `destination`. |
| `method_allowlist` | string[] | OPNet signing | Exact-match against spec `method` (from hints). |
| `max_btc_per_tx` | integer \| decimal string | BTC signing | Sum of non-self outputs must be ≤. |
| `allowed_btc_recipients` | string[] | BTC signing | Every non-self output address must be in the list. |
| `allowed_contracts` | string[] | OPNet signing | Spec `destination` must be in the list (contract address hint). |
| `max_ceremonies_per_hour` | integer ≥ 1 | All ceremonies | Rolling-window approvals cap (this daemon only). |
| `dkg_leader_allowlist` | string[] | DKG | Leader's `nodeId` must be in the list. |

```toml
[gate]
strategy              = "policy"
max_btc_per_tx        = 50000000
allowed_btc_recipients = ["bc1p...", "bc1q..."]
allowed_contracts     = ["0xcontract..."]
max_ceremonies_per_hour = 10
```

### `strategy = "exec"`

| Key | Type | Notes |
|---|---|---|
| `command` | string[] | argv. `command[0]` is the executable. |
| `timeout_sec` | number > 0 | Hard cap on child lifetime (seconds). |
| `working_dir` | string, optional | cwd for the child. |
| `env` | table, optional | Extra environment (added to the daemon's env). |

The daemon writes `CeremonySpec` JSON (bigints → decimal strings) on the
child's stdin and reads the first line of stdout as the decision
(`approve`/`reject`). Anything else → reject. See
`examples/gate-file-approver.sh` for a file-drop pattern.

```toml
[gate]
strategy    = "exec"
command     = ["/etc/otzi/approve.sh"]
timeout_sec = 3600
```

### `strategy = "webhook"`

| Key | Type | Notes |
|---|---|---|
| `url` | string | Full POST URL. |
| `timeout_sec` | number > 0 | AbortController timeout (seconds). |
| `bearer_token_env` | string, optional | Env var holding a Bearer token for outgoing auth. |

The daemon POSTs `CeremonySpec` JSON and expects `{ "decision": "approve" \| "reject" \| "pending" }`. See `examples/gate-web-opwallet/approver.mjs`
for a reference approver that consumes this contract and enforces ML-DSA-44
wallet-signed decisions — **the daemon has no ML-DSA verification code for
gates**; opinionated auth lives in the approver.

```toml
[gate]
strategy         = "webhook"
url              = "http://127.0.0.1:7099/webhook"
timeout_sec      = 600
bearer_token_env = "OTZI_WEBHOOK_TOKEN"
```

## `[deadlines]` (optional)

Ceremony-wide safety-net timeouts. Per-request retry (1s→30s backoff, 5
attempts) is separate and not configurable via the TOML yet.

| Key | Type | Default | Notes |
|---|---|---|---|
| `signing_ms` | integer ≥ 1 | `300_000` (5 min) | Signing ceremony deadline. |
| `dkg_ms` | integer ≥ 1 | `900_000` (15 min) | DKG ceremony deadline. |

The `CLAUDE.md` § Core Architecture table says `exec`/`webhook`/`cli`/`queue`
gates want unbounded signing deadlines (operator review takes hours). This
is an operator decision: set `signing_ms = 86400000` (24 h) or similar on
those daemons.

## `[[triggers]]` (optional)

How ceremonies are initiated on this daemon. Each entry has a `kind` plus
kind-specific params flat in the same table. Zero triggers = nothing can
initiate a ceremony on this daemon (peer-side participation still works).

### `kind = "http"`

| Key | Type | Notes |
|---|---|---|
| `bind` | string | `host:port`. No default — `0.0.0.0` is not assumed. Prefer `127.0.0.1:<port>` or a reverse proxy; see the operator-API-localhost-only note in [`api.md`](./api.md#transport--auth). |
| `auth_token_env` | string, optional | When set, the daemon requires `Authorization: Bearer <value-of-env>` on every request. Missing env at startup → refuse to start. |

### `kind = "cron"`

| Key | Type | Notes |
|---|---|---|
| `schedule` | string | 5- or 6-field cron expression (`croner` syntax). |
| `job_name` | string | Name matching a handler registered via `DaemonDeps.cronHandlers`. Unknown name → startup fails. |
| `timezone` | string, optional | IANA zone (e.g. `Europe/Amsterdam`). Defaults to the daemon's local tz. |

Multiple trigger entries are fine — e.g. one HTTP for operator CLI + one
cron for a daily health-check ceremony:

```toml
[[triggers]]
kind           = "http"
bind           = "127.0.0.1:7080"
auth_token_env = "OTZI_API_TOKEN"

[[triggers]]
kind      = "cron"
schedule  = "0 3 * * *"
job_name  = "daily-healthcheck"
timezone  = "UTC"
```

## Cross-field validation

The parser runs basic coherence checks even before loading the share:

- No duplicate `id` across node + peers.
- No duplicate `party_id` across node + peers.
- `transport.listen` required when `transport.kind = "peer-mesh"`.
- `transport.url` required when `transport.kind = "relay"`.

The share-file alignment check runs at *load* time (not parse):

- Decrypted share's `partyId` must equal `[node].party_id`.
- Decrypted share's `parties` must equal `peers.length + 1`.

Startup with misalignments throws a clear error before anything side-effects.

## Dev shorthand

Sample `daemon.toml` for a 3-node local test (peer-mesh, auto gate, HTTP
trigger):

```toml
[share]
path         = "/tmp/otzi/node-a/share.json"
password_env = "OTZI_SHARE_PASSWORD"

[node]
id              = "node-a"
party_id        = 0
identity_key_file = "/tmp/otzi/node-a/identity.json"
pubkey_book_file  = "/tmp/otzi/node-a/pubkeys.json"

[network]
name      = "testnet"
opnet_rpc = "https://testnet.opnet.org"

[transport]
kind   = "peer-mesh"
listen = "127.0.0.1:9001"

[[peers]]
id       = "node-b"
party_id = 1
endpoint = "ws://127.0.0.1:9002"

[[peers]]
id       = "node-c"
party_id = 2
endpoint = "ws://127.0.0.1:9003"

[gate]
strategy = "auto"

[[triggers]]
kind = "http"
bind = "127.0.0.1:7080"
```
