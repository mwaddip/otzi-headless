# Daemon configuration reference (`daemon.toml`)

Every running daemon is configured by a single TOML file (typically
`/etc/otzi/daemon.toml` on a .deb install; anywhere for tests). This is a
field-by-field reference; for operator workflows (bootstrap → DKG → restart →
fund), see [`install.md`](./install.md).

TOML uses `snake_case` keys. The parser is strict — missing required tables,
unknown enum values, rejected keys and unknown keys (a misspelt
`network.esplora_uri`, a stray table) throw `ConfigError` with the dotted field
path. Every table takes exactly the keys listed below.

## Shape at a glance

```toml
[share]
path         = "/var/lib/otzi/share.json"
password_env = "OTZI_SHARE_PASSWORD"

[node]
id = "node-a"                                # local logging label only
# Paths below are required for real-network transports (not in-memory tests).
identity_key_file = "/var/lib/otzi/identity.json"
pubkey_book_file  = "/var/lib/otzi/pubkeys.json"

[network]
name = "testnet4"                            # "mainnet" | "testnet4" | "signet"
# esplora_url = "https://mempool.example/api"   # optional; CLI only

[transport]
kind                 = "peer-mesh"                       # "peer-mesh" | "relay"
advertised_endpoint  = "node-a.example:8800"             # required for peer-mesh; canonical host[:port]
# url                = "ws://relay.example:9000"         # required iff kind = "relay"

[[peers]]                                                # required for peer-mesh; optional under relay (not used)
endpoint = "node-b.example:8800"                         # required; canonical host[:port]

[gate]
strategy = "auto"                           # see § Gate strategies

[deadlines]
signing_ms = 300000                         # default
dkg_ms     = 900000                         # default

[[triggers]]
kind = "uds"
path = "/var/run/otzi/otzi.sock"
```

## Canonical endpoint form

Every endpoint string (in `[transport].advertised_endpoint` and `[[peers]].endpoint`)
is canonicalized at parse time by `src/util/endpoint.ts::canonicalizeEndpoint`:

- **Default port 8800** if absent: `node-b.example` → `node-b.example:8800`.
- **Lowercase host**: hostnames and IPv6 hex digits; IPv4 unchanged.
- **IPv6 RFC 5952**: longest zero run collapsed to `::`; bracketed in `host:port` form.
- **Rejected**: wildcard hosts (`0.0.0.0`, `::`, `[::]`, `*`, empty), port `0`,
  ports outside `1..65535`, malformed brackets.

The TOML file may contain the raw operator-typed form (e.g. `Node-B.Example`);
canonicalization happens once at parse and is stored normalized in
`DaemonConfig.transport.advertisedEndpoint` / `DaemonConfig.peers[i].endpoint`.

## `[share]` (required)

| Key | Type | Notes |
|---|---|---|
| `path` | string | Absolute path to the Ötzi v4 encrypted share JSON file (mode `0600`). A share written here opens in web Ötzi, and a web Ötzi share can be placed here. While a DKG runs, the new share is staged at `<path>.pending` and moved to `path` only after every node confirmed; a file at `path` is never replaced. No file at startup → the daemon runs in setup mode: no vault is loaded, `sign` returns `409`, and `otzi generate` can run the DKG. |
| `password_env` | string | Name of the env var holding the share-file password. The password itself is never stored in the config. The variable must be set in the daemon's environment even on a node that holds no vault yet, because the DKG encrypts the new share with it. On a .deb install, the unit loads `/etc/otzi/otzi.env` (`root:root`, mode `0600`, one line `OTZI_SHARE_PASSWORD=…`; create it with `sudo install -m 600 -o root -g root /dev/null /etc/otzi/otzi.env`, then edit it). systemd interprets quotes and backslashes in that file: use a password without `"`, `'` and `\`, or quote and escape it. |

At startup the daemon decrypts the share, checks it against `[network].name`,
and checks its `partyId` and `parties` against the pubkey book. Any mismatch
refuses to start; a share that fails a check is never treated as "no vault". A
leftover `<path>.pending` file is logged at warn level and never loaded: it may
be this node's share of a vault the other nodes committed (see
[`cli.md`](./cli.md) § `otzi generate`), otherwise the next DKG overwrites it. A `.pending` that is the loaded share's own
file (a failed removal after the commit left a second name for it) is removed at
startup, with an info line.

## `[node]` (required)

| Key | Type | Notes |
|---|---|---|
| `id` | string | Logical identifier (e.g. `node-a`). Local logging label only — appears in this daemon's own log lines and in gate specs for self. No two nodes need agree on what to call a third; the pubkey book is the cross-node identity. |
| `identity_key_file` | string, optional | Path to this node's PKCS#8 ECDH identity key (generated by `otzi setup`). Required for real transports; optional for in-process tests. |
| `pubkey_book_file` | string, optional | Path to the JSON pubkey book produced by `otzi setup`. Required for real transports. |

`partyId` is not operator-typed. It is derived at startup from the pubkey book
by matching the loaded identity's pubkey to a book entry, and that entry's
`partyId` (assigned by sorted-pubkey-bytes order during bootstrap) is
authoritative. The parser rejects a `party_id` field with an error saying so.

## `[network]` (required)

| Key | Type | Notes |
|---|---|---|
| `name` | `"mainnet"` \| `"testnet4"` \| `"signet"` | The vault's network. The share, every DKG announce and every signing proposal must match it. Other names are rejected (`testnet` → use `testnet4` or `signet`). |
| `esplora_url` | string, optional | Esplora REST API base (`http://` or `https://`) that the `otzi btc *` verbs use. When unset, the CLI uses mempool.space for the network: `https://mempool.space/api` (mainnet), `https://mempool.space/testnet4/api`, `https://mempool.space/signet/api`. **The daemon never reads it.** |

An RPC-URL setting is not supported: it is rejected with an error pointing at
`esplora_url`. The only chain endpoint is `esplora_url`, and only the CLI uses it.

Addresses use the network's HRP: `bc1p…` on mainnet, `tb1p…` on testnet4 and
signet.

## `[transport]` (required)

| Key | Type | Notes |
|---|---|---|
| `kind` | `"peer-mesh"` \| `"relay"` | See `CLAUDE.md` § Transport. `peer-mesh` = direct WebSocket between daemons. `relay` = the headless relay server (`src/transport/relay/server.ts`, run with `otzi relay --listen <host:port>`) routes opaque encrypted frames. |
| `advertised_endpoint` | string | Required when `kind="peer-mesh"`. This node's reachable `host[:port]` (canonical form post-parse; see § Canonical endpoint form). Peers will dial here. Wildcards (`0.0.0.0`, `::`) rejected. |
| `url` | string | Required when `kind="relay"`. WebSocket URL of the relay: `ws://` on loopback or a VPN (e.g. `ws://relay.example:9000`), or `wss://` through a TLS reverse proxy in front of the relay. The daemon redials a relay that is down or drops the connection (backoff 1 s … 30 s). Both the daemon and the relay send a keepalive ping every 20 s, so a proxy idle timeout above 20 s keeps the connection open. |

The parser rejects a `listen` field with an error pointing at
`advertised_endpoint`.

## `[[peers]]` (peer-mesh: required, at least one; relay: optional)

One entry per *other* node in the ring (this node is implied by `[node]`).
Order does not matter — partyIds are derived from the pubkey book, not
peer-array index. `[[peers]]` is a local sanity-check against the
authoritative book; bidirectional endpoint match is enforced at startup.

Under `transport.kind = "relay"` the section may be left out, and a relay config
normally is: the relay routes by `partyId` and the pubkey book names the ring, so
there is no peer list to check. If you do list peers under relay, each entry is
validated as below but nothing uses it.

| Key | Type | Notes |
|---|---|---|
| `endpoint` | string | Required. Canonical `host[:port]` (see § Canonical endpoint form). Must appear as some non-self book entry's `advertisedEndpoint`. |

The parser rejects `id`, `party_id` and `wallet_address` with an error: peer
identity lives in the pubkey book, not operator config.

## `[gate]` (required)

Controls which ceremonies this daemon will join. See [`gates.md`](./gates.md)
for the contract. The `[gate]` table contains `strategy` plus strategy-specific
params directly (flat, not under a sub-table).

| Strategy | Meaning |
|---|---|
| `auto` | Always approve. Default for pure-headless deployments. |
| `policy` | Deterministic rules over the signing spec this node derived from its own analysis of the proposal. Strict-by-default. |
| `exec` | Spawn operator-supplied command; approval = first line of stdout. |
| `webhook` | POST spec JSON to a URL; approval = `{ "decision" }` response. |

A gate only restricts what this node will sign; it never widens it. A rejecting
node stays silent and looks offline to its peers.

### `strategy = "auto"`

No params. Any other key in `[gate]` is refused at startup (`config gate.<key>:
not used by strategy auto`), so policy keys left behind after switching to
`auto` cannot look like rules that are enforced.

```toml
[gate]
strategy = "auto"
```

### `strategy = "policy"`

All keys are optional; each one you set narrows what the gate will approve. A
rule is active iff its key is set, and every active rule must pass.

| Key | Type | Applies to | Rule |
|---|---|---|---|
| `max_sats_per_tx` | integer \| decimal string | Signing | `spec.amount` ≤ cap. `amount` is the sum of non-change outputs, so change back to the vault never counts. |
| `max_sats_per_24h` | integer \| decimal string | Signing | Sum of `amount` over this node's approvals in the last 24 h, plus this spec, ≤ cap. Recorded at approval; held in memory. |
| `allowed_recipients` | string[] \| `"address-book"` | Signing | Every non-change output address must be in the set. Each array entry must be a valid address of `[network].name` (checked at startup). With `"address-book"`, the set is this node's address book, read at each evaluation; a missing or invalid book rejects. |
| `max_fee_sats` | integer \| decimal string | Signing | `spec.fee` ≤ cap. |
| `max_fee_rate` | number \| decimal string | Signing | `spec.feeRate` ≤ cap, in sat/vB. May be fractional. |
| `max_ceremonies_per_hour` | integer ≥ 1 | Signing | Signing approvals by this node in the last hour < cap. |
| `dkg_leader_allowlist` | string[] | DKG | The DKG leader's label must be in the list: `peer-<partyId>` for another node, `[node].id` for this node. |

```toml
[gate]
strategy                = "policy"
max_sats_per_tx         = 5000000
max_sats_per_24h        = "20000000"
allowed_recipients      = "address-book"
max_fee_rate            = 50
max_ceremonies_per_hour = 10
```

Details:

- Caps are non-negative safe integers (TOML integer or decimal string).
  `max_fee_rate` may be fractional.
- The 24 h and hourly windows count every approval this node gives, as leader or
  participant, whether or not the ceremony then completes. Rejects are not
  counted. Windows live in memory and reset on daemon restart.
- **Strict by default.** A configured rule whose input is missing rejects. With
  `allowed_recipients = "address-book"`, a missing book file, an invalid book
  file or any other failed read rejects every signing spec, even one whose
  outputs are all change.
- **`allowed_recipients` entries are validated.** Each array entry must be a
  valid address for `[network].name`; a typo, an address of another network
  (`bc1…` on `testnet4`, `tb1…` on `mainnet`) or a script in hex is a
  `ConfigError` at `gate.allowed_recipients[<i>]` that quotes the entry and
  names the network, and the daemon does not start. Base58 addresses are kept as
  written; an all-uppercase bech32 address is stored in lowercase, which is how
  the analysis reports outputs; mixed-case bech32 is refused (BIP 173).
- The address book is `/etc/otzi/address-book.otzi.json`. Editing it changes the
  allowlist without a daemon restart, which is why it is root-owned (`0640`).
- Signing rules never apply to a DKG spec, and `dkg_leader_allowlist` never
  applies to a signing spec. A policy gate without `dkg_leader_allowlist`
  approves every DKG.
- Unknown keys are rejected.

**Rejected keys.** These keys raise a `ConfigError` at `gate.<key>`:

| Key | Use instead |
|---|---|
| `max_amount`, `max_btc_per_tx` | `max_sats_per_tx` |
| `destination_allowlist`, `allowed_btc_recipients` | `allowed_recipients` |
| `method_allowlist`, `allowed_contracts` | none — a Bitcoin vault signs plain transfers only |

### `strategy = "exec"`

| Key | Type | Notes |
|---|---|---|
| `command` | string[] | argv. `command[0]` is the executable. |
| `timeout_sec` | number, 0 < n <= 2147483.647 | Hard cap on child lifetime (seconds): at the cap the ceremony is rejected and the child gets `SIGTERM`, then `SIGKILL` 5 s later if it is still running. The upper bound is the longest timer Node.js can hold (2147483647 ms, about 24.8 days); a larger value is refused at startup. |
| `working_dir` | string, optional | cwd for the child. |
| `env` | table, optional | Extra environment, added to the daemon's environment. The child never inherits the share password variable (`[share].password_env`) or an HTTP trigger's token variable (`auth_token_env`). |

The daemon writes the ceremony spec as one JSON line on the child's stdin and
reads the first line of stdout as the decision (`approve`/`reject`). Anything
else → reject. The command does not have to read the spec; stdout and stderr are
read up to 64 KiB each. See `examples/gate-file-approver.sh` for a file-drop
pattern.

```toml
[gate]
strategy    = "exec"
command     = ["/etc/otzi/approve.sh"]
timeout_sec = 3600
```

### `strategy = "webhook"`

| Key | Type | Notes |
|---|---|---|
| `url` | string | Full POST URL: `https://…`, or `http://…` to a loopback host only (`localhost`, `127.0.0.0/8`, `::1`). Any other `http://` URL is refused at startup: the decision is this node's security boundary and the Bearer token goes out with every request, so neither may cross a network in clear. For a remote approver, put a TLS reverse proxy in front of it and use its `https://` URL. |
| `timeout_sec` | number, 0 < n <= 2147483.647 | One deadline (seconds) for the whole request: connect, response headers and the full response body. A response that starts early but does not finish in time is a reject. The upper bound is the longest timer Node.js can hold (2147483647 ms, about 24.8 days); a larger value is refused at startup. |
| `bearer_token_env` | string, optional | Env var holding a Bearer token for outgoing auth. |

The daemon POSTs the spec JSON and expects `{ "decision": "approve" | "reject" }`.
See `examples/gate-web-btc-message/` for a reference approver that requires a
Bitcoin message signature from the operator on every decision — **the daemon has
no message-signature code for gates**; opinionated auth lives in the approver.

```toml
[gate]
strategy         = "webhook"
url              = "http://127.0.0.1:7099/webhook"
timeout_sec      = 600
bearer_token_env = "OTZI_WEBHOOK_TOKEN"
```

## `[deadlines]` (optional)

Ceremony-wide timeouts. A node pulls the blobs it needs from its peers until
they arrive or the ceremony deadline passes; a blob still missing at the
deadline fails the ceremony.

| Key | Type | Default | Notes |
|---|---|---|---|
| `signing_ms` | integer, 1 to 2147483647 | `300_000` (5 min) | Signing ceremony deadline. |
| `dkg_ms` | integer, 1 to 2147483647 | `900_000` (15 min) | DKG ceremony deadline. |

The upper bound, 2147483647 ms (about 24.8 days), is the longest timer Node.js
can set; the daemon refuses to start with a larger value.

The defaults suit `auto` and `policy` gates (machine-only; phantom ceremonies
should not linger). With `exec` and `webhook` gates, every signer's decision must
arrive within the ceremony deadline. Operators using human approvals should raise
`signing_ms` (and `dkg_ms`) to cover the slowest approver on every node:
`signing_ms = 86400000` (24 h) or similar.

After a ceremony ends on a node, the node keeps its blobs for a fixed 5 min
(signing) or 15 min (DKG), independent of these deadlines, so lagging peers can
still pull until then.

## `[[triggers]]` (optional)

How ceremonies are initiated on this daemon. Each entry has a `kind` plus
kind-specific params flat in the same table. Zero triggers = nothing can
initiate a ceremony on this daemon (peer-side participation still works).

### `kind = "uds"`

Operator API over a Unix domain socket. Default in deb-installed daemons.

| Key | Type | Notes |
|---|---|---|
| `path` | string (absolute) | UDS socket path. Parent dir must exist with appropriate group perms. |

Example:

```toml
[[triggers]]
kind = "uds"
path = "/var/run/otzi/otzi.sock"
```

Permission model: filesystem ACL on the socket file gates access. The
packaged unit's `RuntimeDirectory=` creates `/var/run/otzi/` as `3770 otzi:otzi`
(setgid and sticky) when the daemon starts and removes it when it stops, so the
socket lands owned by `otzi:otzi` and group-writable. Nothing creates the
directory while the daemon is down; the CLI then finds no socket and reports the
daemon unreachable. Any user in the `otzi`
group can connect; nobody else. The sticky bit keeps a group member from
unlinking or renaming the daemon's socket and binding a look-alike, which the
CLI would trust (`otzi vault` and `otzi btc` check what they print against the
daemon behind this socket).

### `kind = "http"` (loopback only)

Optional TCP listener for advanced use cases (e.g., an operator backend on the
same host). Parser enforces that `bind` is `127.0.0.1`, `::1`, `localhost`, or an
absolute UDS path. External binds are rejected at parse time.

| Key | Type | Notes |
|---|---|---|
| `bind` | string | `host:port`. Loopback enforced — `0.0.0.0` and external IPs are rejected. |
| `auth_token_env` | string, optional | When set, the daemon requires `Authorization: Bearer <value-of-env>` on every request. Missing env at startup → refuse to start. |

Requests must carry a `Host` header naming a loopback host with the listener's port (`127.0.0.1:<port>`, `localhost:<port>`, `[::1]:<port>`); anything else gets `403` (DNS-rebinding protection).

### `kind = "cron"`

| Key | Type | Notes |
|---|---|---|
| `schedule` | string | 5- or 6-field cron expression (`croner` syntax). |
| `job_name` | string | Name matching a handler registered via `DaemonDeps.cronHandlers`. Unknown name → startup fails. |
| `timezone` | string, optional | IANA zone (e.g. `Europe/Amsterdam`). Defaults to the daemon's local tz. |

Multiple trigger entries are fine — e.g. one UDS for the operator CLI plus one
cron job registered by an embedding application:

```toml
[[triggers]]
kind = "uds"
path = "/var/run/otzi/otzi.sock"

[[triggers]]
kind      = "cron"
schedule  = "0 3 * * *"
job_name  = "nightly-sweep"
timezone  = "UTC"
```

## `[bootstrap]`

Bootstrap-time config. Read by `otzi setup` to dispatch to leader vs leaf
bootstrap. Dormant after the pubkey book is written; harmless to leave in
config.

| Field | Type | Required | Notes |
|---|---|---|---|
| `role` | `'leader'` \| `'leaf'` | yes | Leader hosts the registration server; leaves POST to it. |
| `bind` | string | leader-only | `host:port` for the leader's bootstrap HTTP listener. |
| `leader_url` | string | leaf-only | Full URL of the leader's bootstrap endpoint. |
| `parties` | integer, 2 to 255 | relay leader only | Ring size, this node included. A relay config has no `[[peers]]` to count, so the leader states the size; under peer-mesh the size is the number of `[[peers]]` plus this node, and `parties` is refused. A leaf never takes it. |

The parser applies the `parties` rules to every config it reads, `otzi setup`
and daemon start alike. A relay leader whose `[bootstrap]` lacks `parties` fails
with:

```
config bootstrap.parties: required when transport.kind = "relay" and bootstrap.role = "leader"
```

Leaving the section in place after setup is fine as long as it stays valid.

Example (peer-mesh leader):

```toml
[bootstrap]
role = "leader"
bind = "0.0.0.0:7090"
```

Example (relay leader, a ring of 3, bound to its VPN address so only the
members reach it):

```toml
[bootstrap]
role = "leader"
bind = "10.8.0.1:7090"
parties = 3
```

Or bound to loopback, with each member reaching it through an SSH tunnel
(`ssh -N -L 7090:127.0.0.1:7090 <leader-host>`, and `leader_url =
"http://127.0.0.1:7090"` on the member):

```toml
[bootstrap]
role = "leader"
bind = "127.0.0.1:7090"
parties = 3
```

Under relay the leader admits the first `parties − 1` registrations, so its
bootstrap port must be reachable only by the members during setup. `otzi setup`
warns when a relay leader's `bind` is every interface (`0.0.0.0` or `::`). The
peer-mesh leader admits only its `[[peers]]` endpoints, and `0.0.0.0` is fine
there.

Example (leaf):

```toml
[bootstrap]
role = "leaf"
leader_url = "http://node-a:7090"
```

## Cross-field validation

Parse-time checks:

- `transport.advertised_endpoint` required when `transport.kind = "peer-mesh"`.
- `transport.url` required when `transport.kind = "relay"`.
- `[[peers]]` has at least one entry when `transport.kind = "peer-mesh"`; under
  `"relay"` it may be absent or empty.
- `[bootstrap] parties` (integer, 2 to 255) is required on a leader when
  `transport.kind = "relay"`, and refused under `"peer-mesh"` and on a leaf.
- Endpoint canonicalization (see § Canonical endpoint form) on
  `transport.advertised_endpoint` and every `[[peers]].endpoint`.

Startup checks (share and transport-factory, after the pubkey book is loaded):

- The share decrypts, and its network equals `[network].name`.
- The loaded identity's pubkey must match some book entry. That entry's
  `partyId` is the authoritative self.partyId.
- When a share file is present: `share.partyId === selfBookEntry.partyId` and
  `share.parties` equals the number of book entries. Mismatch → abort (config
  swap, stale share or wrong ring).
- For `peer-mesh`: every `[[peers]].endpoint` must match a non-self book
  entry's `advertisedEndpoint`; every non-self book entry's
  `advertisedEndpoint` must appear in `[[peers]]`. Bidirectional.

## Dev shorthand

Sample `daemon.toml` for a 3-node local test (peer-mesh, auto gate, UDS
trigger):

```toml
[share]
path         = "/tmp/otzi/node-a/share.json"
password_env = "OTZI_SHARE_PASSWORD"

[node]
id = "node-a"
identity_key_file = "/tmp/otzi/node-a/identity.json"
pubkey_book_file  = "/tmp/otzi/node-a/pubkeys.json"

[network]
name = "testnet4"

[transport]
kind                = "peer-mesh"
advertised_endpoint = "127.0.0.1:9001"

[[peers]]
endpoint = "127.0.0.1:9002"

[[peers]]
endpoint = "127.0.0.1:9003"

[gate]
strategy = "auto"

[[triggers]]
kind = "uds"
path = "/tmp/otzi/node-a/otzi.sock"
```
